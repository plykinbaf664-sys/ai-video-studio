# Естественный темп

Обратная связь пользователя: длинные промежутки между репликами в31s Story избыточны. Визуальное оформление в целом принято. Продолжительность определяется содержанием; прежние30–40s больше не являются поводом оставлять тишину.

Текущая правка — edits/dry-irony-tight.json: все40 слов,548 кадров/18.2667s. Source/output рассчитаны существующим ядром. Между реальными словами на стыках остаётся около440–560ms вместо ожидания до3.56s. До/после слов сохранены тихие края, в том числе начальные согласные. В финале короткая1.5s выдержка нужна для уже услышанного сравнения; это время чтения, а не пауза между репликами.

Задание задаёт pacing.maximumGapMs=600. src/director/pacing.ts проверяет каждый положительный промежуток в output word map; Studio/prepare отклоняют превышение. Это проверка кандидата таймингов, не автоматическое право удалять тихую речь. Для осмысленной более длинной паузы требуется явное обоснование в плане, не общая фраза «ради иронии».

Музыка продолжает идти на одном постоянном gain; клипы исходного голоса сокращаются в тихих местах, трек не приглушается и не перезапускается на каждой реплике. Цвет/шрифт/палитра/сцены сохраняют выбранную базу. Старый31s MP4 и его монтажные данные остаются отдельно.

Данные нового задания — public/generated/jobs/dry-irony-tight; проверенный результат после реального QC — out/dry-irony-tight.mp4; отчёты — artifacts/jobs/dry-irony-tight. Переиспользование graded cache требует совпадения source SHA, grade, реального cache SHA и original-frame proof; цвет повторно не накладывается. Новый кэш и финальный файл проверяются против оригинала.

Команды: npm run prepare:tight → npm run preview:tight → npm run render:tight. npm run render использует этот путь; render:story явно сохраняет предыдущий31s вариант. Studio: http://localhost:3001/DryIronyTight. Следующий этап — docs/SEMANTIC_DIRECTION_PLAN.md.
