# Контекстная режиссура и библиотека

Актуальное развитие по обратной связи — [DOMESTIC_PHOTO_STORY.md](DOMESTIC_PHOTO_STORY.md), ExecPlan0018: фотографические семейные сцены,4 предметно подобранных кадра, чередование presenter/photo и cutaway, явная series policy для подходящей бытовой иронии. Ниже сохраняется описание исходной версии0017; нынешние команды brief принимают явный смысловой --brief и без него сохраняют нейтральный fallback. Галерея теперь предпочитает фотографические элементы; старый рисунок и0017-export сохранены.

Этап 0017: выбор визуального приёма по задаче конкретной сцены и повторное использование элементов. Реальные исходные слова, source/output mapping, звук постоянного gain и прежние экспорты сохраняются. Новый исходник для расширения не нужен.

## Решение

| Задача | Материал | Как получается | Что переиспользуется |
| --- | --- | --- | --- |
| Бытовая ирония, контраст со словами | Явно вымышленная иллюстрация | Генерация без приватного референса; либо материал с проверенной лицензией | Версия изображения, теги, допустимые контексты, компоновка |
| Объяснить ИИ/процесс | Параметрическая схема process | Нативный React/SVG, узлы и связи из смысла сохранённой речи | Компонент, параметры, раскрытие по словам, токены стиля |
| Сравнить подходы | Схема comparison, без выдуманных метрик | Два подписанных варианта с речевым основанием | Компоновка и анимация |
| Объяснить устройство | Схема system | Центр и 1–3 связанные части, подтверждённые объяснением | Компонент связей и раскрытие |
| Подчеркнуть подачу/развязку | Говорящий, мотивированная смена композиции | Существующий viewport и защищённые области | Проверенный crop/масштаб; никаких случайных зумов |

Сначала искать в своей библиотеке → при отсутствии искать внешние материалы или создавать → проверить назначение/происхождение → зарегистрировать новую версию → использовать. Поиск не превращает найденный файл в разрешённый ассет. Не требуется тащить каждую схему из фотостока или генерировать растровую картинку с нечитаемыми буквами: схемы остаются редактируемыми компонентами.

Внешний поиск реализован для Wikimedia Commons и Openverse: только короткий общий запрос, без исходных кадров/голоса/полной транскрипции. Оба реально вернули результаты по `washing dishes kitchen`; JSON сохранены в artifacts/visual-library/search/. На ранних попытках Openverse истекал timeout; повторная ручная проверка сработала. Материалы из выдачи не скачаны и не использованы в ролике. Лицензия/автор/страница хранятся как данные кандидата, требуется проверка оригинальной страницы и контекста. В частности, доступность изображения не даёт права приписывать реальному человеку семейные обстоятельства.

Первичные условия: [Openverse API](https://api.openverse.org/v1/), [Commons: повторное использование](https://commons.wikimedia.org/wiki/Commons:Reusing_content_outside_Wikimedia), [Pexels license](https://www.pexels.com/legal-pages/license/). Pexels требует API-ключ для автоматического API-поиска; адаптер Pexels в этот этап не добавлен. Его запрет выставлять узнаваемых людей в оскорбительном/негативном контексте — дополнительная причина использовать вымышленную иллюстрацию для сатирического примера. Условия отдельных файлов проверяются отдельно; поисковый индекс не является юридической гарантией.

## Реальные данные и файлы

Канонический каталог остался один: assets/catalog.json. Не создан конкурирующий каталог медиа. Необязательное поле visual в contracts/design-library.schema.json задаёт version, тип illustration/template, темы, intents, стили, теги, происхождение, размеры и provenanceFile. Сам файл имеет SHA256, runtimeFile ведёт в public/generated/assets/, происхождение и условия — отдельный JSON внутри assets/library/visuals/<version-id>/.json. Новая версия получает новый id, регистрация не перезаписывает существующий id.

Начальные элементы: domestic-dishes-v1 (1536×1024, встроенный image_gen, вымышленные взрослые, без приватных входов); diagram-process-v1, diagram-comparison-v1, diagram-system-v1 (собственные параметрические компоненты). Генерационный prompt полностью сохранён в assets/library/visuals/domestic-dishes-v1/provenance.json. Оригинал генерации также сохранён в исходном каталоге Codex. Статус candidate — художественное утверждение не выдумано, исключительное авторское право на AI-output не заявляется.

scripts/lib/visual-library.mjs проверяет физические файлы, происхождение и snapshots; bindVisualAssets готовит runtime-копии, сравнивает их хеши и привязывает provenance к storyboard/render. История повторного использования — artifacts/visual-library/usage/<job>.json. Графическая библиотека и история — локальные; внешней публикации нет.

## Монтажный контракт

src/director/visual-plan.ts — ограниченный VisualPlan, дополнительное поле EditorialJob.visualPlan. План задаёт тему, происхождение решения, список конкретных версий ассетов, beats и объяснения, почему остальное лучше оставить на говорящем. У каждого beat есть точный интервал исходных сохранённых слов и output frames. Каждый shot имеет смысловую причину.

Проверки: вставка не короче45 кадров, промежуток между вставками минимум30 кадров, суммарно максимум45% монтажа; смена сцен с visualPlan не чаще45 кадров. Это текущие консервативные настройки, не универсальная художественная формула. Нельзя применить бытовой contrast к теме AI; разрешены только совместимые темы/intents/стили. Схемы — 2–4 узла, comparison ровно2; подписи до32 символов, без цифр/процентов. Точные цитаты сверяются с сохранёнными словами, редакторские пояснения явно имеют другую роль. Раскрытие после соответствующих слов с запасом; в провайдерском компиляторе также после subtitle tail. Для process допустимы только прямые соседние связи, для system — центр→части, comparison без причинных стрелок. Само соответствие структуры смыслу требует редакторской оценки; синтаксическая проверка не доказывает истинность объяснения. Графики с реальными данными требуют отдельного контракта источников и пока не поддерживаются.

VisualComponents.tsx реализует нативные схемы и вставку. EditorialStory сохраняет один слой текущей речи и прежний Audio. Upper-panel стоит над ведущим; layout guard проверяет реальные DOM-границы панели/метки/текста относительно лица, рук, объектов, safe area и субтитров. В0018 cutaway реализована непрозрачным перекрытием, исходное Video продолжает отрисовку: CSS visibility:hidden может задержать media seek. jobViewport.visible=false описывает фактическую видимость для QC, не остановку часов/голоса. Первоначальный0017-пример использовал только upper-panel; новый002 проверяет фактическую cutaway отдельно.

## Связь с AI-режиссёром

Новый director request включает visualAssets и привязывает каталог/файлы/provenance/renderer/компилятор хешами. Необязательное treatment.visuals в contracts/director-response.schema.json позволяет выбрать только готовые asset IDs и реальные word IDs, задать задачу, узлы и отношения. compileDirectorResponse пересчитывает output-координаты по выбранным source units; старый visualPlan никогда не переносится слепо после перестановки. Для unsupported материала остаются productionNeeds и говорящий.

Qwen text adapter передаёт только смысловые поля библиотеки, без локальных путей, картинок и generation prompt. Новые вызовы Qwen на этом этапе не делались. Старые request hashes после изменения контрактов закономерно устарели; для нового вызова нужен новый request/preflight и отдельное согласование внешнего payload. Исторические MP4 и их доказательства сохранены. Предыдущее разрешение37 JPEG не является постоянным разрешением отправлять новые кадры.

Локальный library:brief — честная эвристика поиска кандидатов по словам, не языковая модель. В0018 он использует явный редакторский --brief и проверяет действие вместе с жанром/отношением контраста; без этого оставляет говорящего. Поддержаны посуда, приготовление еды, ремонт ванной и развешивание белья; неподходящая/неподдержанная сцена остаётся fallback. Для содержательной схемы про ИИ нужны реальная речь или явное редакторское объяснение, поддержанное ею. Автоматический поиск/генерация произвольного B-roll без оценки контекста не запущены; поиск, генерация и импорт выполняются как явные производственные действия.

## Использование

```
npm run library:list
npm run library:find -- --domain ai --intent explain-process --style signal-dynamic
npm run library:brief -- --job visual-001-b --domain domestic
npm run library:search -- --provider commons --query "washing dishes kitchen"
npm run library:search -- --provider openverse --query "washing dishes kitchen"
npm run library:register -- --record reviewed-record.json --file selected-image.png
npm run prepare:context
# PowerShell on this workstation:
$env:AI_VIDEO_SOFTWARE_GL='1'
npm run preview:context
# Inspect storyboard, then:
npm run render:context
node scripts/preview-visual-library.mjs
node scripts/build-visual-library-gallery.mjs
node scripts/serve-visual-review.mjs library 3106
```

`register` требует id, origin, rights (generated/project-original/licensed), review.usable, теги, темы, intents, styles, размеры. Для licensed обязательны автор, sourcePage, licenseUrl, attribution и review.originVerifiedAt. Запись — подтверждение выполненной проверки, не автоматическая юридическая экспертиза. Генерация новых иллюстраций выполняется imagegen, prompt и отсутствие приватных входов фиксируются в provenance; сам CLI скрыто не вызывает платный API.

Studio: ContextDomestic — существующий бытовой источник; VisualLibraryLab —12-секундный стенд process/comparison/system. В props стенда styleId переключается между signal-dynamic/editorial-focus/dry-irony;9 контрольных кадров показывают все сочетания. Это те же три стиля с новыми компонентами, не три новых стиля и не ролик о ещё не записанном ИИ.
