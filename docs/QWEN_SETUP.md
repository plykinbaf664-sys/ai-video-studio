# Подключение Qwen через Alibaba Cloud Model Studio

Реализован Node-адаптер Chat Completions и его подключение к director:generate.25.10.2026 настройки пользователя перенесены из заполненного шаблона в приватный .env.qwen; ключ в примере очищен. Singapore и Qwen3.8-Flash нормализуются в ap-southeast-1/qwen3.8-flash. Один настоящий текстовый вызов выполнен по поручению пользователя: сервис вернул два плана и usage, но локальный QC отклонил ошибки сцен. Исходный ответ сохранён; отдельная редакторская версия имеет явное происхождение, не выдаётся за неизменённый план Qwen. Подробности — docs/QWEN_FIRST_RUN.md. Сетевые unit-тесты по-прежнему используют только локальный симулятор; они не подменяют доказательства реального вызова.

## 1. Настройки

Скопировать `.env.qwen.example` в `.env.qwen`, только если своего файла ещё нет. Заполнить локально, ключ не присылать в чат:

```dotenv
QWEN_ENABLED=false
QWEN_API_KEY=ваш_ключ
QWEN_REGION=регион_рабочего_пространства
QWEN_BASE_URL=полный_OpenAI_compatible_endpoint_из_консоли
QWEN_MODEL=точный_id_доступной_модели_Qwen
QWEN_TIMEOUT_MS=120000
QWEN_MAX_OUTPUT_TOKENS=8192
QWEN_MAX_INPUT_BYTES=131072
QWEN_MAX_RESPONSE_BYTES=1048576
```

Файл `.env.qwen` исключён из Git. Переменные текущего процесса имеют приоритет над файлом. SDK и отдельная установка Qwen на компьютер не нужны; используется встроенный fetch Node24.

В консоли Model Studio выбрать рабочее пространство, регион, доступную модель и API key. Скопировать **OpenAI-compatible** Base URL; API key, регион и endpoint должны соответствовать друг другу. Workspace endpoint имеет вид `https://<workspace>.<region>.maas.aliyuncs.com/compatible-mode/v1`. Регион выбирается явно: Singapore `ap-southeast-1`, Beijing `cn-beijing`, Virginia `us-east-1`, Frankfurt `eu-central-1`, Tokyo `ap-northeast-1`, Hong Kong `cn-hongkong`. Система не выбирает регион передачи данных автоматически. Для Singapore/Beijing/Hong Kong также принимаются соответствующие старые DashScope endpoints. [Официальные endpoints](https://www.alibabacloud.com/help/en/model-studio/base-url), [регионы и область обслуживания](https://docs.modelstudio.console.alibabacloud.com/en/model-studio/regions).

Первая версия работает с **текстовой** моделью Qwen, поддерживающей `response_format: json_object` и отключение thinking. В запросе установлен `enable_thinking:false`; thinking-only модель не подходит этому адаптеру. JSON Object гарантирует формат JSON, но не монтажную корректность: schema и семантические проверки остаются локальными. Модель не переключается автоматически при отказе и не получает скрытого дополнительного запроса «починить JSON». Точный доступный id берётся из выбранного региона; наличие модели локальная диагностика не проверяет. [Официальная документация JSON output](https://help.aliyun.com/en/model-studio/qwen-structured-output), [thinking и ограничения моделей](https://help.aliyun.com/en/model-studio/deep-thinking).

## 2. Проверка без API-вызова

```powershell
npm run director:provider-check
```

Проверяет параметры, допустимый региональный HTTPS endpoint, наличие ключа и лимиты. Не отправляет запрос, не тратит токены, не печатает ключ и не подтверждает доступность сервиса. Пока `QWEN_ENABLED=false`, вызов модели запрещён. Отдельной автоматической проверки /models нет.

## 3. Подготовить новый режиссёрский запрос

```powershell
npm run director:prepare -- --run qwen-first --job dry-irony-tight
npm run director:preflight -- --run qwen-first
```

Использовать новый run после изменения контракта/компилятора. Старые запросы/отчёты сохранены как история; их нельзя молча перепривязать. Старый выбранный Studio job продолжает работать, но его request может требовать новой подготовки для последующей генерации.

Preflight работает при отключённом провайдере и без ключа, если endpoint/регион/модель заданы. Он сохраняет:

- `artifacts/director/qwen-first/qwen.payload.json` — **точный отправляемый JSON** с адресом и лимитами, без ключа.
- `qwen.preflight.json` — состав данных, размер, SHA256, ограничения и готовую команду подтверждения.

Отправляемые данные: реальные слова и таймкоды, цель, исходные монтажные единицы, неопределённости транскрипции, правила монтажа/брендбука, текстовые заметки о приёмах референсов, разрешённые asset IDs и schema ответа. Локальные пути/файловые метаданные, изображения, видео, аудио и чужой видеоряд не включаются. Ключ используется только в Authorization header. Полный исходный request.json содержит локальные данные и **не отправляется целиком**.

Извлечённые ранее кадры доступны для локального просмотра, но этот адаптер их не анализирует. Интонацию/жесты/движение по стенограмме не объявляет изученными.

## 4. Позже — первый разрешённый вызов

После просмотра состава/размера запроса и лимитов аккаунта установить `QWEN_ENABLED=true`. Выполнить показанную preflight команду:

```powershell
npm run director:generate -- --run qwen-first --approve-payload SHA256_ИЗ_PREFLIGHT
```

Это явное разрешение отправить **именно этот** текстовый запрос указанному endpoint/model в Alibaba Cloud. Правило происходит из AGENTS.md п.4 и docs/SAFETY_AND_MEDIA.md: перед внешней передачей приватного материала согласуются состав и получатель. Здесь дополнительный вопрос не задаётся: решение выражает запуск команды с проверенным hash. Наличие ключа или общий запрос «подготовить подключение» не разрешают передачу материала.

Hash связывает контекст, тело, endpoint, модель и лимиты. Изменение запроса/региона/модели/лимитов требует нового preflight. API key в hash не входит. Ограничения: одна попытка на run, без retry и redirects;120s по умолчанию (допустимо1–300s), максимум8192 выходных токенов по умолчанию, ограничение входа/ответа. При таймауте запрос мог быть обработан сервисом: система не повторяет его автоматически. Для осознанного повторного вызова нужен новый run.

Это **не денежный лимит**. Тариф/стоимость зависят от региона и модели; актуальные цены и лимит расходов установить в аккаунте. Preflight не придумывает цену из количества байтов. Usage сохраняется, если сервис его вернул; отсутствие usage не считается нулевой стоимостью.

## 5. Ответ → проверка → монтаж

Ответ без завершённого content, refusal, truncation, слишком большой ответ, HTTP-ошибка или невалидный план отклоняются. API-ошибки не печатают тело сервера/ключи. Модельный content при полученном ответе хранится приватно в run; выбранное решение и MP4 автоматически не создаются.

Успех: `qwen.response.json`, `qwen.receipt.json`, `qwen.attempt.json` и HTML `index.html`. Проверяются два разных замысла, реальные реплики, слово/кадр mapping, цитаты, зарегистрированные референсы, ритм и существующие компоненты. Provenance — `qwen-api`; это отличается от контрольного baseline-adaptation. Непроверенная речь/жесты и художественная оценка остаются отдельными вопросами.

```powershell
npm run director:select -- --run qwen-first --response artifacts/director/qwen-first/qwen.response.json --treatment ID_ВАРИАНТА
npm run director:stage -- --run qwen-first
npm run director:check-studio
```

Studio: `http://localhost:3001/DirectorPreview`. После просмотра выбранного плана используется существующий renderer/QC, например `node scripts/render-editorial-job.mjs --job qwen-first-ID_ВАРИАНТА`. В out/ попадает только MP4 после его фактической проверки. Оформление, source-specific цвет, оригинальная речь и ровный музыкальный фон сохраняются.

## Следующие этапы

1. Настроить доступ и провести **один** согласованный текстовый вызов; оценить два плана рядом с текущим ручным монтажом. Исправить причины отклонения, а не ослаблять защиту речи.
2. Собрать выбранный план в MP4, проверить финальную речь/субтитры/изображение/музыку и посмотреть ролик целиком. Только затем оценивать художественное качество режиссёра.
3. Подключить реальный визуальный разбор через подходящую модель Qwen с отдельным составом/разрешением передачи кадров. Нужны структурированные наблюдения о лице, жестах и кадре; отдельные картинки не заменяют анализ движения/интонации. Текущий текстовый адаптер этого не делает.
4. Повторить на другом реальном исходнике с его стенограммой, безопасными склейками и цветом. После этого расширять автоматическое определение границ нарезки.
5. Доращивать библиотеку схем, графики, иконок/B-roll и ещё2–3 стиля по повторяющимся задачам.3D — после появления конкретной задачи и исполняемого компонента; остальные20 стилей и большой интерфейс пока не приоритет.
