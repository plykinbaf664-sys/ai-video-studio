# Фотографическая бытовая раскадровка — 0018

Пользователь принял направление библиотеки, но попросил меньше иллюстративного AI-вида, больше динамики и отдельные изображения к подходящим бытовым высказываниям. Это обновление творческого правила для подобных историй, не правило вставлять картинку на каждую фразу любого видео.

## Рабочее правило

Нужны одновременно: бытовая тема; явный редакторский контекст иронии; отношение «картинка контрастирует с заявлением»; реальное поддержанное действие в сохранённой речи; готовый фотографический ассет именно этого действия; достаточное время. Тема/слово «посуда» сами по себе ничего не запускают. Нейтральный семейный рассказ, инструкция и объяснение об ИИ остаются вне этой грамматики.

Серия «я сам/сама решил(а)…» может развиваться несколькими различными фотографиями с одной вымышленной семьёй. Смена действий и компоновки создаёт ритм. Открывающее заявление, смысловой поворот и финальный payoff остаются на лице; подводку к развязке допустимо проиллюстрировать, вернувшись до её последних слов. Это не случайный зум и не эффект на каждом слове. Смысл и качество будущей конкретной шутки всё равно требуют редакторского просмотра.

## Реализация

- src/director/domestic-storyboard.ts: чистый локальный планировщик, не языковая модель. На входе независимые units/слова/таймкоды, библиотечные snapshots, выбранный стиль, явный DomesticBrief и policy. На выходе предложения вставок, точные source/output интервалы, причины и отказы. Source/job IDs и конкретные выходные кадры внутри правила не зашиты.
- style-presets/policies/domestic-counterpoint.json: версия domestic-counterpoint-v1. Минимум45 кадров для фотографии, максимум45% хронометража, короткая cutaway до75 кадров, серия до4 разных действий. Соседние фотографии допустимы только с общим seriesId, разными subject/asset IDs, непересекающейся речевой опорой и одним castId. Остальные вставки сохраняют прежние интервалы отдыха. Это ограничение нагрузки, не универсальная художественная формула.
- assets/catalog.json: к visual добавлены необязательные aesthetic, subjects, castId, photoSafety. Старые версии не мигрированы и не перезаписаны. Новый подбор может требовать photographic + конкретный subject: dishwashing, cooking, bathroom-repair, laundry-hanging. Если кадра для ужина нет, нельзя подставить посуду или старый рисунок.
- scripts/prepare-domestic-storyboard.mjs: переносит выбранные предложения в новый EditorialJob. Для совместного кадра рассчитывает уменьшение исходника по объединению защищённых областей, не режет лицо/жесты и блокирует нечитаемо маленькое лицо. Полноэкранный исходник берёт из существующего задания. Сохраняет brief/policy/planner hashes и историю решения. Параметры --base/--id/--brief позволяют повторно использовать правило на другом подготовленном видео.
- VisualPlan / director response: optional policy, presentation family-photo, subject, seriesId. Компилятор пересчитывает output из реальных word IDs; разрешены только готовые зарегистрированные элементы. Внешний текстовый payload содержит семантические метаданные/размеры, но не фото, локальные пути или generation prompts. Нового Qwen-вызова не было.
- ContextVisual: широкие фото занимают804×454 сверху; вертикальное фото может занять экран. Текущая речь остаётся единственным subtitle-слоем. Нормализованные защитные области сгенерированных лиц/рабочих рук вручную отмечены в photoSafety и проверяются относительно текста. Это не автоматический face tracking.

Cutaway реализуется непрозрачным перекрытием исходника. Video остаётся смонтированным и продолжает отрисовку по общему output clock; Audio не меняется. Не использовать CSS visibility:hidden для media: в первом предпросмотре переход на175-й кадр задержался до timeout; после сохранения фоновой отрисовки проверены все внутренние/пограничные кадры cutaway. jobViewport.visible=false описывает фактическую видимость для QC, а не остановку декодера. Реальная проверка финального аудио/следующих source frames обязательна.

## Новые оригинальные фотографии

Все четыре созданы встроенным image_gen без исходных кадров/лица/голоса пользователя. Первая — новый вымышленный семейный кадр; следующие используют только его сгенерированный образец как референс персонажей. Не утверждается, что это настоящая семья или что castId является биометрическим подтверждением личности. Пользователь отклонил экранную метку «Вымышленная сцена»: renderer больше не добавляет её к семейным фотографиям. Исторический экспорт 002 сохраняет прежний вид. ## Команды

```
npm run library:find -- --domain domestic --intent contrast --subject cooking --aesthetic photographic --style signal-dynamic
npm run library:brief -- --job visual-001-b --brief edits/briefs/domestic-counterpoint.json
npm run library:storyboard -- --base visual-001-b --id context-domestic-002 --brief edits/briefs/domestic-counterpoint.json
npm run prepare:photos
$env:AI_VIDEO_SOFTWARE_GL='1'
npm run preview:photos
# Просмотреть storyboard, затем:
npm run render:photos
npm run library:gallery
npm run library:serve
```

Без --brief команда library:brief сохраняет нейтральный fallback, а не объявляет найденное слово поводом для сатиры. В другом видео нужен свой смысловой brief; его может предложить режиссёр, но локальные правила не подменяют понимание жанра моделью. Неподдержанное действие/нужный новый ассет попадает в причину отказа; скрытого платного поиска/генерации или приватной отправки нет.

tests/domestic-storyboard.test.mjs проверяет перенос на другие IDs/формулировки, нейтральные/AI/инструктивные отказы, конкретность действия, неизменность речи/звука/цвета, policy/series/каст, защиту лиц/рук, provider contract и provenance. При неприменимости или отсутствии готовых подходящих фото stage-команда возвращает kept-existing-edit/staged:false и не создаёт новый фотомонтаж.
