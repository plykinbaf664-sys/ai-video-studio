# Повторно используемый Dry Irony

Последняя версия по отзыву пользователя — Tight18.27s /548 кадров/40 слов, docs/PACING_POLICY.md. Старое задание Story31s сохранено как источник сравнения; пользователь отклонил его долгие паузы. Входы/примитивы/стиль общие. Default render обслуживает Tight, render:story явно выбирает предыдущий job.

## Что разделено

- `style-presets/grammars/dry-irony.json` — визуальная грамматика существующего Dry Irony: бренд/ассеты, типографика, группировка речи, допустимые сцены, ритм, движение, переходы, непрерывная музыка. Не содержит исходника, стенограммы и продолжительности. Это кандидат, не новый четвёртый стиль.
- `edits/dry-irony-story.json` — задание для конкретного исходника: hash, реальная стенограмма, source cuts, сцены по output frames, ссылки на исходные слова, ручные параметры лица, цвет, музыкальный фрагмент.
- `src/director/editorial-job.ts` — компиляция задания через существующее временное ядро, пересчёт слов, проверка склеек/цитат/защищённой области. Старый baseline API используется явно только для временного плана; он не управляет новым оформлением.
- `src/design/scenes/` — компоненты. `SpeakerScene` задаёт единые видеочасы; `SpokenQuoteScene` заменяет обычные субтитры крупной текущей фразой; `SplitEnumerationScene` показывает 2–3 услышанных пункта; `ComparisonScene` сравнивает две уже завершённые цитаты. Полный кадр — вариант говорящего.
- `public/generated/jobs/<id>/` — производный план, проверяемый видеокэш и звук; `.cache/jobs/<id>/` — pending render/рабочие файлы; `artifacts/jobs/<id>/` — QC, галерея и кадры; `out/<id>.mp4` — только проверенный результат.

Цитаты выводятся из точных диапазонов `sourceStartMs/sourceEndMs`, не набираются как произвольные подписи. Неизвестные/вырезанные слова отклоняются. Перечень появляется после произнесённого пункта и окончания subtitle tail; итоговое сравнение — после обеих реплик. Графика имеет роль `quote-reprise`, обычная речь — `speech`; второго speech-layer нет. Схема здесь перечисляет бытовые действия: причинные стрелки или выдуманный процесс не добавлены.

## Текущий монтаж

Задание `dry-irony-story`: 31 секунда / 930 кадров / шесть реплик / 40 реальных слов. Source диапазоны 0–5, 7.7–11.6, 13.2–16.9, 20.4–25, 26.6–32.5, 36.9–44.8. Все координаты сцен — output frames, доказательства цитат — source milliseconds.

Постановка: 0s говорящий; 5s крупная текущая фраза; 8.9s говорящий; 12.6s split-перечень; 17.2s возврат к заявлению; 23.1s полный кадр перед развязкой; 28.7s сравнение после завершения фразы. Между сценами прямые композиционные склейки, голос/видео продолжают общий clock. Текст входит за семь кадров с перемещением 10px; случайных эффектов/стоков нет.

Шрифт Onest, палитра и ограничения из существующего Personal Design Kit. Relax Beat — зарегистрированный файл пользователя. Один постоянный gain подложки, короткие края .15/.25s, запас голоса на каждом слове минимум 14dB. Значение −34dBFS — исходная цель уровня музыкального фрагмента, не обещание абсолютной громкости: один gain может быть уменьшен ради запаса голоса. Ducking/подъёмы в паузах/драматические остановки запрещены текущим предпочтением пользователя.

## Запуск и проверки

`npm run studio` → http://localhost:3001/DryIronyTight. Предыдущий Story — отдельная композиция /DryIronyStory. Первый запуск готовит нужные данные; уже работающий Studio подхватывает изменения.

`npm run render` / `render:tight` выполняет prepare → storyboard → render в `.cache` → фактический QC → проверенный файл в `out` → кадры/галерея. `render:story` явно воспроизводит предыдущий31s job. Отдельные текущие команды: prepare:tight / preview:tight. Для другого задания: `node scripts/prepare-editorial-job.mjs --job <id>`, затем такой же preview-editorial-job.mjs и render-editorial-job.mjs --job <id>.

Запущенный Studio не обязателен для рендера: headless storyboard проверяется отдельно, а отсутствие интерактивного сервера честно записывается как not-checked. Текущая композиция — DryIronyTight. Для выбранных режиссёрских заданий есть отдельная DirectorPreview: director:stage готовит данные/раскадровку, затем публикует проверяемый указатель public/generated/director/selected.json. director:check-studio проверяет реальную загрузку выбранного задания. Общего интерфейса управления заданиями пока нет; см. docs/DIRECTOR_WORKFLOW.md.

Если ASR обнаружило лексическое расхождение, renderer выполняет второй проход по акустическим окнам **фактического AAC**, найденным без ожидаемого текста. Затем `review-editorial-speech.mjs` проверяет source recognition / waveform / хеши / акустическую энергию спорных участков. Неизвестный случай блокирует выдачу. Поддержанные свидетельствами расхождения записываются в hash-bound `speech-review.json`; статус остаётся `review-required`, а не «подтверждённая человеком расшифровка». Ложное распознавание в тишине не создаёт новых субтитров. `final.asr.json` и `final.windows.asr.json` сохраняют обе версии, включая их ошибки. Для повторного QC без дорогостоящего рендера есть `--qc-only`, который отклоняет изменённые входы/код/MP4. Не использовать его после изменения оформления или таймингов.

Фактический отчёт после успешной выдачи: `artifacts/jobs/dry-irony-story/REPORT.md`, `validation.json`, `media.json`, `final.asr.json`, `steady-music.json`, `loudness.json`, `index.html`, `final-frames.png`. Наличие документации не подтверждает, что рендер уже прошёл: это подтверждают только текущие файлы/хеши/отчёты. Визуальный статус обновляется отдельно после просмотра контрольных кадров.

Существующие `render:v3` и `render:styles` оставлены для воспроизводимости прежних вариантов. Исторические выходы не удаляются и не заменяются новым заданием.

## Как добавить другое видео правильно

1. Сохранить старый исходник и его монтажные данные. Для текущего ingest-контракта новый источник кладётся в `public/source.mp4`; не заменять его посреди задания. Полная библиотека произвольных источников пока не реализована.
2. Выполнить `npm run inspect:source` и локальную транскрибацию. Проверить реальные слова, паузы и начала/концы фраз. Получить собственную пару plan/transcript, привязанную к новому hash. Нельзя использовать нашу стенограмму вместо новой.
3. Создать `edits/<id>.json` по структуре текущего задания, сохранить `presetId: dry-irony`. Указать реальные размеры и ручную область лица; проверить каждую крупность и safe zones. Новый формат source/rotation пока требует адаптации ingestion/QC: автоматическое кадрирование не заявляется.
4. Задать полные source cuts, затем output scenes; цитаты указывать диапазонами сохранённых слов. Сцена должна иметь цель и конкретный reference beat. Не добавлять схему, если мысль не требует схемы. Для каждого нового source подобрать собственный SDR color profile, а не копировать ручную маску текущего лица.
5. Использовать только зарегистрированные разрешённые ассеты. Подготовить, просмотреть раскадровку, затем рендерить и читать фактический QC. После проверки кадров прослушать речь/склейки/фон от начала до конца.

Локальная основа семантического выбора сцен реализована отдельно в проходе0013: docs/DIRECTOR_WORKFLOW.md. Следующий этап — подключённый провайдер, настоящий анализ материала и сравнение предложений с ручным монтажом на двух реальных исходниках. Автономный AI Director, настоящий3D и остальные стили пока не реализованы.

## Место на диске в этой рабочей среде

При подготовке обнаружен ENOSPC на C:. Кэш модели сохранён с проверкой хеша и перенесён в `D:\AI-Video-Studio-Cache\ai-video-studio\whisper`; `.cache/whisper` — NTFS junction на него. Никакие исходники, монтажные данные, архивы и готовые ролики не удалены. Незавершённая прежняя папка build/ сохранена и больше не используется новым job-путём.

Сохранённая build/ также перенесена в `D:\AI-Video-Studio-Cache\ai-video-studio\build-before-0011` (проверен bundle hash), а node_modules/.cache — в `node-build-cache` (сверены все 17 файлов). Оба прежних пути восстановлены junction, поэтому исторические команды сохраняют доступ. Это локальные зависимости данной рабочей машины: при резервном копировании учитывать цели junction на D:. Они не являются пользовательскими исходниками.

`scripts/lib/editorial-runtime.mjs` создаёт временную локальную сборку, ссылающуюся на существующий public/ вместо копирования всех исторических WAV/MP4. Это локальный runtime, не переносимый deployment bundle. Если на диске проекта меньше 1GiB и доступен D: с запасом, временная сборка/Chrome/FFmpeg направляются в указанный кэш D:. Можно явно задать `AI_VIDEO_SCRATCH` перед запуском. Итоговый MP4 по-прежнему в out/ проекта; рабочие пути записаны в плане прохода. Для выдачи на C: всё равно нужно место под финальный MP4 и отчёты.
