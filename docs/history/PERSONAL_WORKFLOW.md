# Personal Design Kit — рабочий процесс

Исходный комплект сохранён в `ai-video-studio-personal-design-kit-v1/`. Карта импорта и SHA-256: `artifacts/design-kit/import.json`. Компоненты размещены в `src/design/personal/`, исходные пресеты — `style-presets/personal/`, исполняемые контракты — `style-presets/runtime/personal-*.json`. Брендбук, референсы, активы находятся в архитектурных `brandbooks/`, `reference-library/`, `assets/`. Основной редактор, `src/index.ts`, `src/Root.tsx` и канонический 30-секундный план сохранены.

## Запуск

`npm run studio:personal` открывает три настоящие композиции на http://localhost:3002. Это отдельный entrypoint `src/personal-entry.ts`; demo-cues из комплекта не используются. `npm run studio` по-прежнему запускает основной редактор.

Подготовка первой сборки: `npm run prepare:personal`, локальное ASR через `scripts/transcribe-audit.py --manifest .cache/personal/asr-reference-jobs.json --cache .cache/whisper` в `.venv-transcribe`, затем `node scripts/refine-personal-timing.mjs`, `node scripts/preview-personal.mjs`. Последняя команда собирает `build-personal`, проверяет Studio и сохраняет контрольные кадры. `npm run render:personal` рендерит, полностью декодирует и проверяет каждый результат перед копированием в `out/`. Повторная сборка после изменения кода требует нового `preview-personal.mjs`.

Текущая выборка — 15 секунд монтажа из одного реального исходника: source 0–5; 7.7–11.6; 36.9–43 → output 0–5; 5–8.9; 8.9–15. Это три законченные реплики, а не непрерывный отрезок. Кадры, склейки и голос совпадают во всех вариантах, скорость 1.0. Сравнение намеренно фиксирует макроритм, чтобы оценивать оформление честно. Менять ритм под стиль можно следующим отдельным планом с повторным QC.

## Что управляет стилем

Исполняемый контракт задаёт шрифт, размеры и насыщенность, безопасный слот, форму/цвет карточки, анимацию, допустимые компоненты, сохранение голоса, политику звука, склеек и кадрирования. Предоставленные правила направлений сохранены в исходных пресетах. Нормализованные контракты используются реальным рендерером. Произвольные функции не поддерживаются молча.

Сейчас стиль выбирается явно через композицию. `src/director/select-style.ts` также реализует объяснимую рекомендацию по явно заданной цели: история → Editorial Focus; объяснение с доказательствами → Signal Dynamic; ироническая развязка → Dry Irony. Ручной выбор имеет приоритет; неизвестный стиль/несовместимый брендбук отклоняется. Это правила, не работающий AI Director. Ни рекомендация, ни успешный рендер не означают визуальное утверждение: все три стиля остаются candidate.

Editorial: тихая редакционная карточка, мягкое появление, медная линия под произнесённой развязкой, исходный голос.

Dynamic: более быстрые появления, смысловые выделения и указатель трёх монтажных шагов; финал — верхняя схема из уже услышанных цитат и единственная текущая реплика, снизу исходный портрет целиком. Один тихий оригинальный SFX в паузе. Никаких придуманных чисел.

Irony: сдержанные светлые карточки, статичная композиция и выдержанная исходная пауза, минимальная метка на реально произнесённой развязке; один тихий оригинальный SFX после речи.

## Графическая библиотека и референсы

Сейчас используются SemanticBrackets из комплекта, адаптированная карточка текущей речи, QuoteFlow и разделённая композиция. 15 скриншотов просмотрены; это реальные источники решений по типографике и компоновке, а не разрешённый B-roll. Видео-референсов в комплекте нет. По фото можно оценить композицию, шрифтовой масштаб, палитру, материал и свет. Для ритма, переходов, движения схем и звуков нужны короткие видео, желательно с отмеченными 5–15 секундами и описанием конкретного приёма.

Следующее развитие: 3–4 отточенных блока (тезис, сравнение, процесс, доказательство), единые токены и правила количества акцентов; затем лицензированная коллекция SVG-иконок с источником/лицензией каждого набора; затем настоящая 3D-сцена для графов/объектов, свет/камера/материалы и тест на этом компьютере. Настоящее 3D пока не реализовано. Данные схем должны происходить из речи/подтверждённых фактов; для текущего исходника сложная 3D-диаграмма не обоснована.

## Материалы и ограничения

Финальная подготовка звука: `src/design/personal/audio-policy.json` задаёт голос 0.84 (-1.51dB) и исходные тихие SFX. Причина — обнаруженные декодированные AAC-пики выше full scale; это не доказательство клиппинга при самой записи. Перед выдачей аудио собирается напрямую из исходных диапазонов с запасом по уровню, а H.264 копируется без повторного кодирования изображения. Выполняются повторные ASR/waveform/frame-проверки и проверка sample peaks. `npm run render:personal` включает этот этап. На уже готовых видеокадрах он отдельно проверен командой `node scripts/master-personal-outputs.mjs`.

Onest/Inter загружены из официальных репозиториев с OFL и проверкой кириллицы; точные источники, лицензии и хеши — `artifacts/design-kit/fonts.json`. В комплекте обнаружены четыре MP3, хотя документы говорят об их отсутствии. Они сохранены, но права не подтверждены; они не копируются в публичные ассеты и не используются. Четыре исходных WAV и SVG зарегистрированы с предоставленным подтверждением происхождения. Это не сторонняя музыка под выдуманной лицензией.

Проверки: исходный хеш; границы целых слов; source→output для всех 22 слов; максимум две строки и один текущий текстовый слой; геометрия безопасной области при рендере каждого кадра; полное декодирование MP4; фактические waveform/кадры против источника; повторное локальное распознавание финального звука. Схема повторяет две уже услышанные цитаты в приглушённой исторической роли, не выдаёт их за текущую речь. SRT рядом с MP4 не создаётся.

Фонетическую точность ASR до миллисекунды и качество произношения в самом начале записи алгоритм не гарантирует. Сравнение кадров подтверждает исходные моменты, а не заменяет человеческое чтение по губам. Художественное утверждение стиля остаётся за пользователем.
