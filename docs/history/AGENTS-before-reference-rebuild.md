# AI Video Studio — инструкция для Codex

## Назначение
AI Video Studio — проект локальной, в перспективе автоматизированной системы **смыслового профессионального видеомонтажа**. Вход: исходное видео и настройки/референсы. Выход: воспроизводимый MP4, монтажный план, отчёт проверки. Графика, субтитры, монтаж и звук должны усиливать мысль, а не создавать случайный шум.

**Текущий статус:** комплект документации — проектные требования, а не доказательство наличия работающей реализации. При первом запуске обязательно осмотри фактический репозиторий, не выдумывай существующие команды и модули.

## Как работать с контекстом
- Используй прогрессивное чтение: **не открывай все документы перед каждым изменением**. Сначала `AGENTS.md`, потом только связанные с задачей файлы.
- Цель и ограничения → `docs/PROJECT_CONTEXT.md`.
- Фактический и целевой стек/границы модулей → `docs/ARCHITECTURE.md`.
- Сквозные сценарии → `docs/SYSTEM_MAP.md`.
- Проверки и команды → `docs/VERIFICATION.md`.
- Решения и нерешённые вопросы → `docs/DECISIONS.md`.
- Стиль инженерной работы → `docs/AGENT_WORK_STYLE.md`.
- Семантика монтажа и временные шкалы → `docs/EDITING_CONTRACT.md`.
- Пресеты и визуальная режиссура → `docs/STYLE_SYSTEM.md` + `style-presets/`.
- Приватность, права и внешние провайдеры → `docs/SAFETY_AND_MEDIA.md`.
- Крупные задачи → `.agent/PLANS.md`; первый этап → `.agent/plans/0001-first-render.md`.

## Истина и предположения
Код, манифесты, тесты и **фактический рендер** определяют реализованное поведение. Эти документы фиксируют намерения пользователя; они не подтверждают, что функции уже работают. Не заменяй существующий код предлагаемой архитектурой без необходимости. Не перезаписывай чужие инструкции без проверки.

## Непереходимые границы продукта
1. Исходники не изменять; монтаж и производные ассеты хранить отдельно.
2. Разделять источник, стенограмму, факты, интерпретации AI и монтажные решения. Не придумывать цитаты, числа, доказательства и чужую речь.
3. Любые временные координаты в edit plan должны явно указывать шкалу (источник/итог), особенно после удаления пауз и склеек.
4. Внешняя передача приватного видео или голоса, публикация и необратимые операции — только после явного разрешения пользователя.
5. Использовать только разрешённые к использованию внешние материалы; хранить источник и лицензию при импорте.
6. Нельзя называть рендер или AI-функцию рабочими без реальной проверки. Ошибки и нерешённые вопросы сообщать прямо.

## Порядок разработки
Сначала минимальный сквозной путь **входное видео → композиция → предпросмотр → проверенный MP4**. Затем распознавание/таймкоды → смысловой edit plan → 3–4 доведённых стиля → QC/перепросмотр → остальные стили и Auto Director. На первом этапе не строй огромный интерфейс и не имитируй работу AI заглушками.

## Завершение задачи

Основа дизайн-библиотеки: docs/DESIGN_LIBRARY_STATUS.md. Правила исполняемого baseline находятся в style-presets/runtime/baseline-unbranded.json, связаны с реальными компонентами; npm run design:check проверяет схемы, зависимости и активы. brandbooks/catalog.json и reference-library/catalog.json пока пусты. 20 JSON в корне style-presets остаются неисполняемыми проектами. Новые стили и брендбуки нельзя объявлять утверждёнными по факту появления контракта/реестра. Направления для согласования: docs/STYLE_DIRECTION_BRIEF.md.

Мануал наполнения: docs/DESIGN_LIBRARY_MANUAL.md. Входные папки: brandbooks/media/, reference-library/media/, assets/library/. Описания: templates/design/. design:add регистрирует только draft/candidate, без копирования медиа в public и без утверждения; сначала проверяет предлагаемый каталог. При добавлении материалов не меняйте текущий MP4/план и не трактуйте reference-only как разрешение использовать файлы.

Текущая проверка точности речи/субтитров: docs/SPEECH_SYNC_QC.md. Нельзя возвращать начальный титр «Всё решаю сам» без подтверждённого исходного аудио. loadEdit и Studio проверяют происхождение текстовых акцентов, рендер делает повторное локальное ASR и проверку фактического звука/изображения до замены готового MP4. ASR review-required не выдавать за полностью подтверждённую расшифровку. Данные и отчёты speech QC — в artifacts/speech-qc/, рабочие файлы — .cache/speech-qc/.
Текущая визуальная база и доказательства: docs/BASELINE_VISUAL_QC.md; следующий дизайн-этап: docs/DESIGN_SYSTEM_PLAN.md. Компоненты src/design — baseline-unbranded, не утверждённый стиль. Не возвращайте одноимённый SRT рядом с MP4: это создаёт дополнительный источник текста в плеере.

Проверенная реализация второго этапа: docs/STAGE2_STATUS.md. SemanticCut исполняет приватный план из public/generated; команда npm run render:semantic. Исторические проектные документы описывают и будущие направления; не считайте их все реализованными.

Сообщи: что реально изменено; какие команды реально запускались; какой файл/путь подтверждён; что проверено и не проверено; известные ограничения; следующий минимальный шаг. Для сложной межмодульной работы веди ExecPlan.
