# Исполняемый контракт дизайн-библиотеки

Дополнение Personal Design Kit: теперь к baseline добавлены три исполняемых **candidate**-контракта, 15 draft-референсов, один draft-брендбук и 7 новых проверяемых активов (в сумме 8 с Manrope). Отдельный рендерер реально использует Onest/Inter, карточки, semantic brackets, split screen и допустимые SFX. Историческое описание baseline ниже сохраняет прежние ограничения именно основного редактора. Текущий мануал: `docs/PERSONAL_WORKFLOW.md`; подтверждение файлов и QC — `artifacts/personal/`.

Реализован технический фундамент, без новых утверждённых стилей. Контрольная команда: npm run design:check. Машинный отчёт — artifacts/design/catalog.validation.json.

## Какие правила исполняются

- Ритм: конкретные клипы по-прежнему задаёт edit plan; minimumLeadMs/minimumTailMs используются для выявления склеек без запаса речи. Автоматического режиссёра/генератора ритма нет.
- Субтитры: из контракта берутся размер группы, предел символов, разрыв между фразами и время удержания. Максимум две строки, сохранённая речь и происхождение цитат проверяются отдельно.
- Типографика и композиция: реальный зарегистрированный шрифт, веса, размеры, безопасные зоны, карточка и палитра подключены к src/design.
- Графика: доступны только существующие subtitles и quote-callout, один текстовый фокус. Неизвестный компонент отклоняется.
- Движение: длительность появления цитаты задаётся контрактом; reframe отсутствует и отклоняется.
- Звук: поддерживается только исходный голос. Запрос музыки, SFX или замены голоса отклоняется. Это проверяемая политика, не реализация звукового микшера.
- Переходы: только прямые склейки общей A/V Sequence; crossfade/wipe отклоняются.
- Кадрирование: только contain без автоматического поиска лица. Изменение этого требования нельзя тихо проигнорировать.

## Проверки реестра

contracts/design-library.schema.json проверяет формы данных и неизвестные поля. scripts/lib/design-library.mjs проверяет уникальность ID, ссылки Style→Asset/Brandbook/Reference, файл/хеш/лицензию активов, границы локальных путей и ссылок, доступность графических/аудио/переходных возможностей. Нельзя объявить техническую базу утверждённым брендбуком или запустить будущий стиль одним переключением JSON-флага.

prepare:assets вызывает проверку автоматически до копирования файлов. Поэтому проверка применяется при studio/dev/build и render:semantic. Добавление каталога не превращает описательные проекты в готовые рендеры.

Для наполнения созданы brandbooks/media/, reference-library/media/ и assets/library/, шаблоны templates/design/ и команда design:add. Импорт сохраняет статусы draft/candidate, проверяет весь предполагаемый каталог до записи, защищает запись блокировкой и сохраняет прежнюю версию. Исходные файлы не перемещаются и автоматически не применяются. Мануал: DESIGN_LIBRARY_MANUAL.md.

## Воспроизведение

1. npm run design:check — каталог и реальные зависимости.
2. npm test — регрессии, включая неизвестные эффекты, неполные контракты, испорченный/отсутствующий актив, отсутствующую лицензию, выход пути за каталог, отсутствующие брендбуки/референсы.
3. npm run lint и npm run build — типы, линтер и реальная сборка с JSON-контрактом.
4. npm run studio -- --port=3001 — живой предпросмотр.
5. node scripts/check-design-preview.mjs — после build и запуска Studio: контрольные PNG из текущей композиции, проверка загруженного текста и геометрии Studio; отчёт artifacts/design/preview.validation.json. Сценарий использует локальный Chrome на Windows, порт рендера 3102; чужой сервер на :3000 не трогает.

На этом этапе новый MP4 не экспортируется, готовый out/semantic-cut-synced.mp4 не заменяется. ASR review-required и три ручных вопроса остаются в docs/SPEECH_SYNC_QC.md. Проверка каталога и PNG не заменяет будущую приёмку трёх стилей со звуком.

## Следующий шаг

Согласовать направления из STYLE_DIRECTION_BRIEF.md и получить конкретные референсы/брендбук. Заполнить каталоги реальными данными, затем реализовать первые три направления и провести визуальное сравнение на одном фрагменте. Пустые каталоги обозначают недостающие входные материалы, а не готовую библиотеку.
