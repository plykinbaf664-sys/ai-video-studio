# Context Engineering — AI Video Studio

Этот набор файлов подготовлен по структуре плагина `context-engineer`. Он **не является исходным кодом видеоредактора** и не утверждает, что компоненты, упомянутые в архитектуре, уже существуют.

## Как установить
Распакуй **содержимое** этого комплекта в корень существующего репозитория `ai-video-studio` — рядом с `package.json` и будущим `src/`. Не вкладывай целую папку комплекта внутрь проекта. Перед заменой существующих `AGENTS.md` и документации сравни их и сохрани полезные локальные инструкции.

```text
ai-video-studio/
├── AGENTS.md                  # короткий навигатор для Codex
├── README_CONTEXT_ENGINEERING.md
├── docs/
│   ├── PROJECT_CONTEXT.md    # цель продукта и сценарии
│   ├── ARCHITECTURE.md       # границы и планируемый стек
│   ├── SYSTEM_MAP.md         # критические потоки
│   ├── VERIFICATION.md       # лестница проверок
│   ├── DECISIONS.md          # подтверждённые решения / открытые вопросы
│   ├── AGENT_WORK_STYLE.md   # рабочие принципы агента
│   ├── EDITING_CONTRACT.md   # семантика и монтажные таймкоды
│   ├── STYLE_SYSTEM.md       # модель режиссуры и стили
│   └── SAFETY_AND_MEDIA.md   # приватность и лицензии
├── .agent/
│   ├── PLANS.md              # формат ExecPlan
│   └── plans/
│       └── 0001-first-render.md
├── contracts/
│   └── edit-plan.schema.json # контракт данных (проектный, v0)
└── style-presets/
    ├── README.md
    └── *.json                # 20 дизайн-пресетов, ещё не рендерятся
```

## Как использовать
Codex сначала читает `AGENTS.md` и проверяет текущее дерево проекта. Остальную документацию открывает только по задаче. Если структура реального проекта отличается — обновляет указатели после ревизии. Каждое утверждение о доступных скриптах и интеграциях сверяет с репозиторием.

## Поддержка и ограничения
- Документация объясняет намерения; тесты, схемы и кодовые проверки фиксируют стабильные контракты.
- При появлении реальных модулей заменить предположительные пути на существующие.
- Подвергшиеся изменению архитектурные решения фиксировать в `docs/DECISIONS.md`.
- Не встраивать API-ключи и приватное видео в репозиторий.
- При расширении логики и формата edit plan обновлять схему и тесты вместе с кодом.
